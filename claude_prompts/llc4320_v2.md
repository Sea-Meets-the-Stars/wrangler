The format is: mask files (`hFacC/S/W.bits`) are a flat bit-per-gridpoint mask, LSB-first per byte, `13*FS*FS` bits per vertical level, levels concatenated back-to-back (so `NZ = filesize / bytes-per-level`); `<field>.<10-digit iteration>.shrunk` files hold only the *wet*-point values, as a stream of big-endian float32, in the same flat facet-major/row-major order as the mask's set bits — i.e. classic run-length-free "boolean mask compression," matching what I'd found `xmitgcm.llcreader` implements conceptually for ECCO's distribution (question 11's earlier finding). Decoding one level requires no MATLAB-specific machinery: read that level's mask bits, popcount them for the read length, unpack big-endian floats into the `True` positions of a zero-filled array, reshape to `(13, FS, FS)`. The MEX's `'facets'` output mode (as opposed to its `'map'` mode, which also runs a `twodify()` reprojection into a single lat/lon-like raster) returns exactly that native `(13, FS, FS)` layout — no facet-rotation logic involved at all, and it's already dimensionally what `xmitgcm`/`dbof` expect, so that's the layout this port targets; `twodify()` was intentionally not ported.

Ported the algorithm to pure Python/NumPy in `wrangler/ogcm/llc_v2.py`: `mask_file_for_field`, `mask_bytes_per_level`, `detect_nz`, `read_mask_level`, `level_byte_offset` (cumulative popcount across levels, for future `k>0` fields — trivially 0 for the surface), `decompress_level`, `read_shrunk_field`, and a `read_sst` convenience wrapper.
